# 더빙 기능: 구현 예정 목록

1차 구현(AI 목소리 + 내 목소리 복제, 비동기 작업 + S3)에서 의도적으로 뺀 항목과,
구현 중에 발견한 후속 작업을 정리한다.
우선순위가 높은 항목부터 적는다.

## 0. [출시 전 필수] 운영 환경 분리 (지금 EC2를 운영으로 전환)

- **현재 상태**: 서울 EC2 + RDS + 버킷 `magic-editor-server` 한 벌을 개발 서버로 쓴다. Swagger는 켜 두고, 보안 그룹은 회사·집 IP만 허용한다.
- **방침**: 출시할 때 지금 환경을 운영으로 전환하고, 개발 서버는 작게 새로 만든다.
  RDS(자동 백업, EC2와 분리)는 실제 사용자 데이터에 필요하고, 개발 서버는 데이터가 사라져도 괜찮기 때문이다.
- **절차**
  1. 개발 서버를 만든다: EC2 한 대에서 앱과 PostgreSQL을 Docker로 함께 실행한다. 버킷은 `magic-editor-dev-<임의 문자열>`로 따로 만들고, Swagger는 켠다.
  2. 앱 debug 빌드의 서버 주소를 개발 서버로 바꾼다. 로컬 개발(IntelliJ)의 `AWS_S3_BUCKET`도 개발 버킷으로 바꾼다.
  3. 지금 서버를 운영으로 정리한다.
     - 시험 데이터를 지운다 (예: 시험 계정 `deploy-check@test.com`).
     - 환경변수 파일에 `SPRINGDOC_API_DOCS_ENABLED=false`, `SPRINGDOC_SWAGGER_UI_ENABLED=false`를 넣는다.
     - 도메인과 HTTPS(Caddy)를 붙인다.
     - 하루 사용량 제한(1번)과 요청 횟수 제한을 넣은 버전을 배포한다.
  4. 보안 그룹에서 443(HTTPS)을 전체에 연다.
  5. 앱 release 빌드는 `https://api.<도메인>`을 바라보게 한다.
  6. 저장소 공개 여부를 정한다. 지금 저장소는 공개(public)라서 서버 주소와 API 구조(`docs/app-api-guide.md`, `docs/openapi.json`)가 공개되어 있다.
     비공개로 바꾸거나 문서에서 운영 주소를 뺀다. 비공개로 바꾸면 GHCR 이미지의 공개 여부와 EC2의 이미지 받기 방식(지금은 로그인 없이 받음)도 함께 바꾼다.
- **주의**: 전환 전까지는 로컬과 서버가 같은 버킷을 쓴다. 두 DB의 id가 모두 1부터 시작하므로 같은 파일 경로(`dubbings/1/1.mp3`)를 쓸 수 있다.
  로컬에서 작업을 지우면 서버의 같은 경로 파일도 지워진다. 서버에 지켜야 할 데이터가 생기면 1번 절차의 개발 버킷 분리를 먼저 한다.

## 1. [출시 전 필수] 회원별 하루 사용량 제한

- **이유**: Typecast는 글자 수로 과금한다 (Lite 플랜 월 20만 자). 제한이 없으면 사용자 한 명이 한 달 크레딧을 모두 쓸 수 있다.
- **구현 방향**
  1. 설정값 `dubbing.daily-character-limit`를 추가한다 (예: 5,000자).
  2. `DubbingJobService.create`에서 오늘 만든 내 작업의 글자 수 합계를 조회한다.
  3. 합계 + 이번 요청 글자 수가 한도를 넘으면 429 예외를 던진다.
  4. FAILED 작업을 합계에 넣을지 정한다 (넣지 않으면 실패 반복으로 한도를 우회할 수 없는지 확인).
- **필요한 것**: 429용 공통 부모 예외(`TooManyRequestsException`)와 `GlobalExceptionHandler` 처리.

## 2. [API 키 발급 후] AI 목소리 목록 교체

- **현재 상태**: `PresetVoice`에는 동작 확인용 `DYLAN`(`tc_672c5f5ce59fac2a48faeaee`) 하나만 있다. 영어 이름의 목소리다.
- **확인한 사실 (2026-11-02, 무료 플랜 키)**
  - 공식 문서의 예시 id(`tc_674fc...`)는 실제 id가 아니다. 그 id로 합성하면 404 `VOICE_NOT_FOUND`가 온다. 반드시 목록 API에서 id를 가져온다.
  - `GET /v3/voices?model=ssfm-v31` 결과는 631개이고 언어 필드가 없다. 한국식 이름을 가진 목소리가 145개 있다.
  - 오류 응답 형식: `{"error_code": "VOICE_NOT_FOUND", "message": "..."}`.
- **후보 (모두 ssfm-v31, 감정 7종 이상 지원)**

  | 이름 | id | 성별·연령 | 주 용도 |
  |---|---|---|---|
  | 서연 | `tc_637cbfeef7f00f21e8a1c6c8` | 여성·청년 | 설명·강의 |
  | 유진 | `tc_64818767272f62f8ddb73948` | 여성·청년 | 오디오북 |
  | 서현 | `tc_69f2e455ea79fd197aa0476f` | 여성·청년 | 아나운서, 대화 |
  | 진우 | `tc_632293f759d649937b97f323` | 남성·청년 | 다큐, 광고, 오디오북 |
  | 한준 | `tc_618b1849ef7827cfea34ea1e` | 남성·청년 | 다큐, 오디오북 |
  | 태우 | `tc_6800a387534948f191cc952b` | 남성·청년 | 설명·강의, 오디오북 |

- **구현 방향**
  1. 후보의 미리 듣기(preview_url)나 직접 합성한 샘플을 들어 보고 목소리를 고른다.
  2. 고른 목소리를 `PresetVoice`에 추가하고, `TypecastTtsClient.providerVoiceIdOf`에 id를 매핑한다.
  3. `DYLAN`을 지우면 기존 작업 행의 `preset_voice` 값이 enum과 맞지 않게 된다. 지우기 전에 데이터 처리 방법을 정한다.

## 2-1. [발견] S3 업로드가 실패하면 재시도할 때마다 크레딧을 다시 쓴다

- **발견 내용**: Worker는 S3 업로드 실패를 일시적인 오류로 보고 재시도한다. 재시도는 합성부터 다시 하므로 최대 3번 크레딧을 쓴다.
- **영향**: S3 설정 없이 `TYPECAST_API_KEY`만 넣고 더빙을 요청하면 요청 1건마다 크레딧을 3번 쓰고 FAILED가 된다.
- **현재 대안**: S3 설정을 마치기 전에는 서버에 `TYPECAST_API_KEY`를 넣지 않는다.
- **구현 방향 (택1)**
  1. 서버 시작 시 키는 있는데 버킷 이름이 없으면 경고 로그를 남기고 Worker를 멈춘다.
  2. 업로드 실패만 따로 재시도한다 (합성 결과를 잠시 보관할 곳이 필요하다).

## 3. 감정 프리셋

- **이유**: Typecast는 `normal | sad | happy | angry | whisper | toneup | tonedown`과 강도(0.0~2.0)를 지원한다. 같은 문장을 다른 느낌으로 읽게 할 수 있어 더빙 품질을 높인다.
- **구현 방향**: 더빙 요청에 선택 필드 `emotion`을 추가한다. `DubbingJob`에 컬럼을 추가하고(V3 마이그레이션), Typecast 요청의 `prompt`에 넣는다.
- **주의**: 목소리마다 지원하는 감정이 다르다. 목소리 목록 응답의 `emotions` 값을 함께 확인한다.

## 4. 녹음 문장 읽기 검증

- **이유**: 남의 녹음 파일을 올려 복제하는 악용을 줄인다.
- **현재 대안**: 앱 녹음 화면에서 무작위 문장을 보여 주고 읽게 한다 (서버 검증 없음).
- **구현 방향**: 서버가 문장을 발급하고, 녹음 파일을 음성 인식(STT)으로 변환해 발급한 문장과 비교한다. STT 서비스 선택이 먼저 필요하다.

## 5. S3 오래된 파일 자동 삭제

- **이유**: 결과 파일이 계속 쌓이면 저장 비용이 늘어난다.
- **구현 방향**: S3 콘솔에서 버킷의 **수명 주기 규칙**을 추가한다 (예: `dubbings/` 접두사, 생성 후 90일 뒤 삭제). 코드 변경은 없다.
- **주의**: S3 파일이 지워져도 DB 작업 행은 COMPLETED로 남는다. 보관 기간을 앱에 안내하거나, 같은 기간이 지난 작업 행도 정리하는 배치를 추가한다.

## 6. 회원 탈퇴 시 정리

- **현재 상태**: 회원 탈퇴 기능이 아직 없다.
- **구현 방향**: 탈퇴 기능을 만들 때 아래를 함께 처리한다.
  1. 내 목소리 삭제 (Typecast 슬롯 해제 포함).
  2. 더빙 작업 행과 S3 파일 삭제.
  3. Apple 로그인 수단이 있으면 Apple 연결을 철회한다 (`POST https://appleid.apple.com/auth/revoke`).
     철회에는 Apple refresh 토큰이나 access 토큰이 필요하다. 탈퇴할 때 앱이 Apple 로그인을 한 번 더 받아 authorizationCode를 보내고,
     서버가 `/auth/token`에서 토큰으로 바꾼 뒤 철회한다. `client_secret`은 Apple 개발자 계정의 비밀키(.p8)로 서명한 JWT다.
- **필요한 이유**: Google Play와 App Store 모두 앱에서 계정을 만들 수 있으면 계정 삭제 기능을 요구한다.
- **주의**: member 도메인이 dubbing 리포지토리를 직접 부르면 안 된다 (도메인 경계 규칙). Facade로 조합하거나, 회원 탈퇴 이벤트를 발행하고 dubbing이 구독하게 한다.

## 7. [기술 부채] OSIV(Open Session In View) 끄기 검토

- **발견 내용**: Spring Boot는 OSIV를 기본으로 켠다. Spring은 Hibernate 커넥션 모드를 `DELAYED_ACQUISITION_AND_HOLD`로 설정한다. 그래서 HTTP 요청 처리 중에 한 번 잡은 DB 커넥션은 요청이 끝날 때까지 유지된다.
- **영향**: 목소리 등록·삭제(`VoiceService`)는 트랜잭션 밖에서 Typecast를 호출한다. 하지만 OSIV 때문에 그 시간에도 커넥션을 잡고 있을 수 있다. Worker 경로는 HTTP 요청이 아니므로 영향이 없다.
- **현재 판단**: 목소리 등록은 드문 작업이라 지금 규모에서는 문제가 되지 않는다.
- **구현 방향**: `spring.jpa.open-in-view=false`로 끈다. 그 전에 컨트롤러에서 지연 로딩을 쓰는 곳(예: `MemoResponse.from`의 tags)을 Service 안에서 DTO로 바꾸거나 fetch 전략을 조정해야 한다.

## 8. Worker 처리량 늘리기

- **현재 상태**: Worker는 한 번에 한 작업만 처리한다. 작업 하나가 10초 걸리면 시간당 약 360건이다.
- **구현 방향**: 대기열이 길어지면 Typecast 동시 요청 한도(Lite 5개) 안에서 처리 스레드를 늘린다. 작업 가져오기 쿼리가 `for update skip locked`를 쓰므로 여러 스레드나 여러 서버가 같은 작업을 중복 처리하지 않는다.
- **추가 검토**: 완료를 앱에 알리는 푸시(FCM)를 붙이면 앱의 상태 조회(폴링) 횟수를 줄일 수 있다.

## 9. [출시 전 필수] 로그인 보안 보완

- **Apple nonce 필수화**: 지금은 `nonce`를 보내면 검증하고, 보내지 않으면 건너뛴다. iOS 앱이 nonce를 보내기 시작하면 필수로 바꾼다 (`AppleApiClient.fetchProfile`).
- **카카오·구글 aud 검사**: 지금은 토큰이 진짜인지만 확인하고, 우리 앱을 위해 발급된 토큰인지는 확인하지 않는다.
  그래서 다른 앱이 받은 사용자 토큰으로도 우리 서비스에 로그인할 수 있다.
  - 구글: idToken의 `aud`가 우리 앱의 OAuth client ID와 같은지 확인한다. Apple처럼 공개키로 직접 검증하는 방식으로 바꿀 수 있다.
  - 카카오: 토큰 정보 API(`/v1/user/access_token_info`)의 `app_id`가 우리 앱 ID와 같은지 확인한다.
- **Apple 설정**: Apple Developer Program 가입, 번들 ID 등록, Sign in with Apple 기능 활성화. 서버 환경변수 `APPLE_CLIENT_IDS`에 번들 ID를 넣는다.
